# 论文初步构想：面向 ABC—古琴减字谱编配的 Benchmark 与经验演化 Agent

> 状态：初步研究构想  
> 目标：明确论文故事、任务定义、数据划分、方法路线与实验框架；后续随数据规模和预实验结果迭代。  
> 暂定投稿方向：The Web Conference（WWW）或相关 Agent / Digital Humanities / Symbolic Music 方向会议。

## 1. 暂定题目

### 主标题候选

**GuqinBench: Benchmarking Experience-Evolving Agents for ABC-to-Jianzipu Fingering Arrangement**

### 其他候选

1. **From Melody to Fingering: Benchmarking Agents for Guqin Jianzipu Arrangement**
2. **Learning to Arrange Guqin Jianzipu from Limited Experience**
3. **GuqinAgent: Experience-Guided ABC-to-Jianzipu Arrangement with Structured Musical Feedback**

当前更推荐第一个标题，因为它同时容纳两个主要贡献：大规模 benchmark 与小样本 harness 学习。

## 2. 一句话研究问题

给定 ABC notation 表示的旋律与调弦信息，Agent 能否生成音高正确、可以演奏、左右手指法连贯，并具有古琴表现特征的结构化减字谱；进一步地，在不依赖大规模模型参数训练的情况下，Agent harness 能否利用少量高质量经验持续提升编配能力？

## 3. 核心论文故事

ABC 到减字谱不是普通的字符转写。ABC 主要描述音高、时值与音乐结构，而减字谱还需要确定弦位、徽位、散按泛、左右手指法、移动方式与表现技法。因此，真正的任务是从旋律生成一种完整的古琴演奏实现：

\[
\text{ABC melody}
\rightarrow
\text{playable and expressive Jianzipu realization}
\]

一个给定音高通常存在多种合法实现，但这些实现并不具有相同的演奏难度、上下文连贯性、音色效果和古琴风格。单音音高可以局部确定，指法与表现技法则依赖前后文，是一个多解的序列规划问题。

本文首先构建一个曲目级、音符级对齐的 ABC—减字谱 benchmark，保留每个发声音符对应的弦位、徽位、散按泛、左右手指法和附属技法。随后，以冻结的基础模型为主要设定，研究一个能够通过少量高质量实例、失败反馈和历史经验不断改进的 Agent harness。Harness 的可学习对象不是模型参数，而是提示、谱例检索、记忆、任务分解、工具调用、反思与候选选择策略。

确定性的音乐知识检查作为数据质量控制、自动评价和 Agent 环境反馈的一部分，不作为论文的中心叙事。

## 4. 预期贡献

1. **GuqinBench**：一个较大规模、曲目级组织、音符级对齐的 ABC—减字谱数据集与 benchmark。
2. **分层任务定义**：把 ABC 到减字谱编配拆分为发声位置、左右手取音和表现轨迹三个层次。
3. **多解感知的评价协议**：区别参考谱完全匹配、音高/功能等价和专家认可的合理替代。
4. **经验演化 Agent harness**：冻结基础模型，通过少量高质量经验优化提示、记忆、工具和控制流程。
5. **全面实验**：比较规则、检索、提示工程、工具 Agent、经验演化 harness 与模型微调方法。
6. **古琴指法分析**：重点研究左手移动、技法连贯性、可演奏性及其与古琴韵味的关系。

## 5. 任务定义

### 5.1 输入

- ABC notation；
- 调弦；
- 节拍、速度、调号等元数据；
- 可选：流派、版本、曲目类型或演奏偏好。

### 5.2 输出

输出为结构化减字谱事件序列。每个发声事件至少包括：

- 对应的 ABC 音符或和弦；
- 弦号；
- 散音、按音或泛音；
- 徽位及徽分；
- 右手指法；
- 左手取音指法；
- 前置、后置或持续性左手技法；
- 与前后事件的连接关系；
- 原始减字符号或可渲染表示。

### 5.3 三层输出结构

#### 第一层：发声实现

\[
(\text{string}, \text{open/stopped/harmonic}, \text{hui})
\]

回答“这个音在琴上哪里发出”。

#### 第二层：左右手取音

回答“使用什么左右手指法把这个音弹出来”。

#### 第三层：表现轨迹

包括吟、猱、绰、注、上、下、进、退等，回答“这个音怎样进入、延续或连接到下一个音”。

### 5.4 对齐单位

“一一对应”定义为 ABC 发声音符与减字谱发声锚点之间的对齐，不强迫每个装饰或移动技法单独对应一个 ABC 音。

建议同时发布：

1. `note_alignment`：ABC 音符与减字谱发声事件之间的映射；
2. `technique_graph`：技法附着对象、持续范围及跨事件连接关系。

## 6. 数据集构想

### 6.1 目标规模

- 最低目标：100 首完整曲目；
- 理想目标：500—1000 首；
- 重点不是仅增加音符数量，而是覆盖不同调弦、曲目、版本和指法现象。

### 6.2 质量等级

- **Bronze**：自动提取完成，通过基本格式与完整性检查；
- **Silver**：完成音高、结构和对齐检查，异常显式保留；
- **Gold**：经过人工逐句或逐音核验；
- **Expert**：由古琴演奏者进一步评价可演奏性、指法与表现技法。

大规模语料可以 Silver 为主体；Gold 和 Expert 子集负责校准自动指标、开发 harness 和进行最终人工评价。

### 6.3 数据划分原则

所有划分必须以曲目为单位，而不是随机拆分音符。相同曲目、异版、重复采集和高度相似版本应归入同一数据组，避免泄漏。

建议将数据组织为：

- **Training pool**：大部分曲目，可用于模型微调、检索库构建和统计建模；
- **Harness development pool**：从 training pool 中划出的少量高质量曲目，用于提示、记忆和流程迭代；
- **Validation set**：用于选择模型、超参数和 harness 版本；
- **Public test set**：输入公开，可用于本地调试，标签可以部分公开；
- **Hidden test set**：标签不参与开发，用于最终主结果；
- **Expert set**：规模较小、现象丰富，进行盲评和细粒度指法分析。

一个可行的初始比例是：

- Training pool：70%；
- Validation set：10%；
- Public test：10%；
- Hidden test：10%。

Harness development pool 不额外占用测试集，而是从 Training pool 内部选择，例如 10、20 或 40 首 Gold 曲目。

### 6.4 开源形式

开源前需明确谱面及衍生标注的再发布权。根据权利范围，可以采用：

- 完整开放全部配对数据；
- 开放训练与验证数据，隐藏测试标签；
- 开放结构化特征与短片段，通过评测服务器评价完整曲目；
- 发布版本化数据卡、来源说明、清洗规则与修订日志。

## 7. 方法：Experience-Evolving Agent Harness

### 7.1 设计原则

- 主要实验冻结基础模型参数；
- 使用少量高质量曲目形成经验；
- 学习对象是 harness，而不是模型权重；
- 最终 harness 在隐藏测试集上冻结运行；
- 所有方法使用明确且可比较的调用、token、时间和工具预算。

### 7.2 Harness 的组成

- 系统提示与领域知识；
- ABC 和减字谱的结构化表示；
- 乐句切分与分层规划；
- 相似谱例检索；
- 音高、弦位和徽位工具；
- 候选生成与排序；
- 自我检查与反思；
- 成功/失败经验记忆；
- 工具调用和终止策略。

### 7.3 初步学习算法：经验引导的 Harness 演化

1. 用当前 harness 编配开发曲目；
2. 收集自动指标、结构化诊断和专家反馈；
3. 提炼失败模式及可复用编配经验；
4. 更新 prompt、memory、检索策略或任务分解；
5. 在未参与该次修改的开发曲目上复验；
6. 只保留跨曲目稳定提升的修改；
7. 定期合并重复经验，删除无效或相互冲突的规则；
8. 冻结最终 harness，在隐藏测试集上评价。

后续可以比较不同的 harness 学习算法：

- 简单经验累积；
- 相似实例检索；
- 反思后写入 memory；
- 经验过滤与压缩；
- 基于开发集分数的 prompt 搜索；
- Meta-agent 修改工作流；
- 多臂老虎机或贝叶斯优化选择 harness 组件；
- 作为扩展实验的参数化训练。

## 8. 微调与数据公平性

### 8.1 不建议的方案

不建议只在一个很小的数据子集上比较所有方法。这样虽然“数据公平”，但无法回答完整训练数据是否能显著提升微调方法，也会削弱大规模 benchmark 的价值。

也不应让微调方法使用全部训练数据、harness 只使用少量数据，然后只报告一个结果并直接宣称 harness 更优。两者的数据预算不同，结论会含混。

### 8.2 推荐：双协议实验

#### 协议 A：Equal-Data Low-Resource

所有可学习方法只使用相同的少量 Gold 曲目，例如：

- 5 首；
- 10 首；
- 20 首；
- 40 首。

比较：

- few-shot prompting；
- retrieval；
- harness experience learning；
- SFT/LoRA；
- preference tuning（若可行）。

这个协议回答：

> 在相同且有限的高质量监督下，哪种适配方式更有效？

它是证明 harness 数据效率的主实验。

#### 协议 B：Best-Available-Resource

- 微调方法可以使用完整 Training pool；
- 检索方法可以索引完整 Training pool；
- Harness 的经验更新仍限制为少量 Gold 曲目，但可以把大规模 Training pool 作为只读检索库；
- 所有方法在同一个 Hidden test set 上评价。

这个协议回答：

> 当每类方法使用其最自然的资源配置时，最终能够达到什么水平？

完整数据微调结果可以被视为强基线或性能上限，而不是与小样本 harness 完全同预算的比较。

### 8.3 数据规模曲线

建议对至少一种参数化方法和 harness 方法同时报告：

\[
N \in \{5, 10, 20, 40, 100, \text{Full}\}
\]

如果总曲目数不足，可以缩减为：

\[
N \in \{5, 10, 20, 40\}
\]

横轴是使用曲目数或有效发声事件数，纵轴分别报告音高、指法、连贯性和专家评价。该实验比单一 full-data 微调结果更能支持“少量经验即可改善 harness”的核心主张。

### 8.4 资源报告

除准确性外，应同时报告：

- 训练或优化所用曲目数；
- 人工反馈小时数；
- 模型调用次数；
- 输入/输出 token；
- 推理时间；
- GPU 训练成本；
- 每首测试曲目的平均成本。

样本效率和计算效率可以成为 harness 方法的重要优势。

## 9. 实验系统

### 9.1 必要基线

1. **Rule-based**：固定优先级选择弦位、徽位和基本指法；
2. **Retrieval-based**：检索相似旋律或乐句并迁移编配；
3. **Zero-shot prompting**；
4. **Few-shot prompting**；
5. **Knowledge-augmented prompting**；
6. **Tool-using Agent with fixed harness**；
7. **Experience-evolving Agent harness**；
8. **SFT/LoRA baseline**；
9. 可选：**Preference optimization** 或其他参数化适配。

规则方法与提示词工程方法都应纳入，因为它们分别提供领域规则下限和通用模型直接能力基线。实验重点不是堆积大量提示词变体，而是形成从固定规则、静态提示、工具使用到可学习 harness 的清晰能力阶梯。

### 9.2 主实验

在相同隐藏测试集上比较：

- 音高与发声位置；
- 左手指法；
- 右手指法；
- 技法完整性；
- 乐句级连贯性；
- 可演奏性；
- 风格与专家偏好；
- 成本和延迟。

### 9.3 Harness 消融

- 无工具 / 有工具；
- 无检索 / 有检索；
- 无 memory / 静态 memory / 演化 memory；
- 无反思 / 固定反思 / 选择性反思；
- 逐音生成 / 乐句级规划 / 分层规划；
- 只反馈总分 / 提供细粒度反馈；
- 不同经验集大小。

### 9.4 泛化实验

- 见过与未见曲目；
- 常见与少见调弦；
- 简单与复杂左手技法；
- 短句与长句；
- 单一候选与多候选音高；
- 不同曲目时期、风格或版本；
- 不同基础模型；
- 将学到的 harness 迁移到未参与优化的模型。

## 10. 评价体系

### 10.1 音高与结构

- ABC 发声音符覆盖率；
- 音高正确率；
- 调弦一致率；
- 弦位和徽位合法率；
- 可解析减字谱比例；
- 多音或复合事件完整率。

### 10.2 与参考谱的比较

- 完全匹配；
- 弦号匹配；
- 散按泛匹配；
- 徽位匹配；
- 左手指法匹配；
- 右手指法匹配；
- 技法集合与技法序列匹配；
- 音高/功能等价匹配。

参考谱不是唯一正确答案，因此完全匹配不能作为唯一主指标。

### 10.3 左手连贯性

- 相邻事件物理移动距离；
- 单位时间移动距离；
- 不必要换弦次数；
- 不合理大跨度移动；
- 同指连续运动难度；
- 移动方向反复程度；
- 技法与前后音的冲突；
- 长乐句姿态可持续性。

这些指标应由古琴演奏者参与定义，并使用 Expert set 检验其与人工判断的相关性。

### 10.4 专家评价

采用盲评与随机顺序，对生成版本进行成对比较或分项评分：

- 音高和谱面正确性；
- 可演奏性；
- 左手连贯性；
- 右手自然度；
- 表现技法适切性；
- 余韵利用；
- 古琴风格自然度；
- 整体偏好。

报告评审者背景、评审者一致性和置信区间。

## 11. 关键研究问题

- **RQ1**：现有规则、检索、提示和 Agent 方法在 ABC 到减字谱任务上的能力边界是什么？
- **RQ2**：少量高质量经验能否显著提升冻结模型的 Agent harness？
- **RQ3**：Harness 学习与模型微调在不同数据规模下各自具有什么优势？
- **RQ4**：工具、检索、记忆、反思和分层规划分别贡献多少？
- **RQ5**：局部音高正确性能否转化为乐句级指法连贯性和专家认可的古琴风格？
- **RQ6**：在一种模型或曲目上学到的 harness 能否迁移到新模型、新曲目和新调弦？

## 12. 预期主要结论

以下是假设，不应在实验前写成既定事实：

1. 通用模型可以生成表面合理的减字谱，但在弦位、徽位和复杂左手技法上存在系统性错误；
2. 固定规则能保证部分局部正确性，但难以处理多解选择和长程指法；
3. 大规模微调可能提高局部符号匹配，但需要更多训练数据和计算资源；
4. 经验演化 harness 在少量 Gold 数据下具有更好的样本效率；
5. 检索、分层规划和经验 memory 对左手连贯性的贡献可能大于单纯增加提示长度；
6. 自动局部指标与专家韵味评价之间可能存在差异，需要多指标联合评价。

## 13. 风险与应对

### 风险一：数据规模达不到微调需求

应对：

- 使用预训练语言模型进行 LoRA 等参数高效适配；
- 以音符事件数和乐句数同时报告数据规模；
- 做低资源曲线而非只做 full-data 训练；
- 将参数化方法定位为强基线，不强求训练一个完整领域模型。

### 风险二：参考谱不是唯一答案

应对：

- 使用多解感知指标；
- 引入功能等价判断；
- 对代表性样本进行专家合理性评价；
- 有条件时收集同曲异版作为多参考。

### 风险三：自动指标不能代表韵味

应对：

- 将韵味拆成可解释维度；
- 验证自动指标与专家评分的相关性；
- 保留专家主观评价作为核心结果之一。

### 风险四：Harness 在开发集上过拟合

应对：

- 使用曲目级独立验证；
- Harness 每次更新后在未用于该次修改的开发曲目上验证；
- 限制迭代次数并保留完整修改日志；
- 最终冻结后只运行一次隐藏测试。

### 风险五：数据无法完整开源

应对：

- 尽早完成权利审查；
- 准备公开特征、标注规范、评测代码和隐藏测试服务等替代发布方案；
- 在论文中清楚区分可复现、可访问和可再分发。

## 15. 最近的执行优先级

1. 固定数据 schema，特别是 `note_alignment` 与 `technique_graph`；
2. 统计现有数据中左右手技法字段的覆盖率和可靠性；
3. 建立曲目去重、完整性检查和质量等级；
4. 制作首批 10—20 首 Gold harness development set；
5. 保留独立曲目作为 validation 和 hidden test；
6. 实现 Rule、Retrieval、Zero/Few-shot 三个最低基线；
7. 实现固定 harness Agent；
8. 再设计第一版经验演化算法；
9. 数据规模达到一定程度后增加 LoRA/SFT 基线；
10. 与古琴演奏者共同确定左手连贯性指标和专家评价表。
