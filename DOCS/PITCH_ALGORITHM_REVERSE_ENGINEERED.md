# 丝桐里 App 减字谱↔简谱 音高算法 逆向报告

本报告基于对 `libapp.so`（Flutter/Dart AOT，arm64）的直接反汇编，所有结论
均标注了二进制内的可核验地址。工具：仓库内 `.codex_deps/capstone` +
`pyelftools`，脚本 `scripts/disasm_func.py`、`scripts/find_pool_xrefs.py`。

## 0. 方法与可信度声明

- **逆向来源**：反汇编 `.text`（vaddr = 文件偏移 = `0x250000` 起），结合
  blutter 生成的对象池快照 `work/blutter_out/pp.txt` 与 `objs.txt`。
- **可信度分级**：
  - ★★★ 已在二进制中逐字节核对（常量表、引用点、运算指令）。
  - ★★  从指令序列读出，逻辑自洽，但未单步仿真寄存器。
  - ★   需要进一步动态验证（Frida hook 实参）。
- **不诚实的地方先说**：我曾尝试用仓库里 1900 条已抓取事件做经验拟合来
  "验证"公式，但拟合命中率只有 10%~27%，原因是这批数据的简谱音高带有
  作者手写的八度/音级约定，与"按音物理音高"不是同一个量。因此本报告
  的**算法主体来自反汇编，经验数据只用于证伪、不用于证立**。

---

## 1. 核心结论（一句话）

App **不是**从减字谱"计算"出简谱音高，而是把减字谱和简谱**各自独立地**
折算成一个"绝对音高数"（类 MIDI 半音数），再比较两者是否一致；不一致
就触发"减字不匹配"提示，并提供候选减字替换。绝对音高的计算依赖**四张
写死在二进制里的查表** + 调弦对象 `Nab` 的全局转调。

---

## 2. 二进制内的四张关键查表（★★★ 逐字节核对）

地址是对象池偏移 `[pp+0x...]`，由 `add xN,x27,#hi,lsl#12 ; ldr xM,[xN,#lo]`
加载（`x27` = 对象池基址 `0x600080`）。`hi<<12 + lo` 即为表地址。

| pp 偏移 | 表内容 | 含义 | 引用点数 |
|---|---|---|---|
| `0x135e8` | `[0,2,4,5,7,9,11]` | 大调音阶：简谱音级 1–7 → 半音 | 3 处 |
| `0x13d50` | `[36,31,28,24,19,28,12,28,19,24,28,31,36]` | 13 个徽位的**泛音**音程（半音） | 1 处 |
| `0x13d70` | `[-5,-3,0,2,4,7,9]` | 7 根弦相对 F（=第3弦）的音级偏移 | 9 处（最密集） |
| `0x17340` | `[0,2,5,7,9,12,14]` | 7 根空弦相对第1弦(C)的半音向量 | 2 处 |

另有音名表 `["C","#C","D","bE","E","F","#F","G","bA","A","bB","B"]` @`0x17370`
（C 根）和 `["1","#1",…,"7"]` @`0x13d58`（简谱根）。

### 2.1 13 徽表的物理含义（★★★ 已证明）

`[36,31,28,24,19,28,12,28,19,24,28,31,36]` = `round(12·log₂(谐波次数))`，
谐波次数按古琴传统为 `[8,6,5,4,3,5,2,5,3,4,5,6,8]`（关于第 7 徽对称）：

```
徽 1,13 → 8 倍频 → 36 半音      徽 4,10 → 4 倍频 → 24 半音
徽 2,12 → 6 倍频 → 31 半音      徽 5, 9 → 3 倍频 → 19 半音
徽 3,6,8,11 → 5 倍频 → 28 半音  徽 7    → 2 倍频 → 12 半音(八度)
```

核对：`12·log₂(8)=36.0`、`log₂(6)=31.02`、`log₂(5)=27.86→28`、`log₂(4)=24`、
`log₂(3)=19.02→19`、`log₂(2)=12`，**全部精确命中**。所以这张表是**泛音**
物理表，不是按音表。

### 2.2 调弦对象 `Nab`（★★★）

`objs.txt:1334` 起的 6 个 `Nab` 实例，每个是 `(调名, List<int>(8))`：

```
正调     [0,0,0,0,0,0,0, 0x11]      # 0x11=17
紧二五   [0,1,0,0,1,0,0, -17]
慢三弦   [0,0,-1,0,0,0,0, 5]
紧五弦   [0,0,0,0,1,0,0, 7]
正调     [0,0,0,0,0,0,0, 5]
正调     [0,0,0,0,0,0,0, 0]
```

下标 0–6 = 每根弦的半音微调（紧=+1，慢=−1）；**下标 7 = 全局转调**（决定
`1=?` 的那个半音数）。同名"正调"出现多个不同下标 7，说明"正调"是定弦、
而 `1=C/1=F/1=Bb` 等是另一维度，二者正交——这与 `AGENT_REPRODUCTION_GUIDE.md`
里"正调描述定弦、1=X 描述首调调号，不能互推"的结论一致。

## 3. 两条音高计算路径（★★ 指令级读出）

### 路径 A：简谱 → 绝对音高（`0x63faa0` / `0x679600`）

```
0x63fab0  mov x0,#7        ; 越界检查：音级必须 < 7
0x63fabc  ldr MAJ[x2]      ; x2 = 音级(1..7), 取 MAJ[音级-1]
0x63fad8  mov x16,#0xc
0x63fadc  mul x1,x2,x16    ; octave * 12
0x63faec  add x0,x2,x1     ; 绝对 = MAJ[deg-1] + 12*octave
```
附带临时记号修正（`cset eq` / `mov x2,#-1` 分支处理升/降/还原）。

**语义**：`简谱绝对音高 = MAJ[音级−1] + 12·八度 + 临时记号`。这是标准的
首调→固定调换算，没有任何琴学物理。

### 路径 B：减字谱 → 绝对音高（核心，`0x68f230`，`vJk_Pab::_anon_closure`）

这是 9 处引用最密集的函数簇。关键指令：

```
0x68f23c  ldr x2,[FIFTH_REL]        ; x2 = STRING_FIFTH 表 [-5,-3,0,2,4,7,9]
0x68f268  ldur x5,[x4,#0x37]        ; x5 = note.八度
0x68f26c  ldur x6,[x4,#0x2f]        ; x6 = note.弦号(0..6), 越界检查 < 7
0x68f298  ldur w1,[x2+x6*4+0xf]     ; x1 = STRING_FIFTH[弦号]
0x68f2ac  mov x16,#0xc
0x68f2b0  mul x4,x5,x16             ; x4 = 八度 * 12
0x68f2c0  sub x1,x4,x5'             ; x1 = 八度*12 − STRING_FIFTH[弦号]
   ... blr (徽位虚函数,返回徽位贡献 x1') ...
0x68f2f4  sub x2,x0,x1'             ; x2 = (八度*12 − 弦偏移) − 徽位贡献
0x68f304  ldur x0,[x1,#0x3f]        ; x0 = 全局转调 (Nab 下标7)
0x68f308  add x3,x2,x0              ; 最终 = 八度*12 − 弦偏移 − 徽位贡献 + 全局转调
```

**语义（指令直读）**：

```
减字绝对音高 = 八度·12 − STRING_FIFTH[弦号] − 徽位贡献 + 全局转调
```

注意三个要点：
1. 弦号项**取负号**——这是因为 App 内弦号方向与音高方向相反（1 弦最低）。
2. 徽位贡献**也取负**，且来自一次虚函数调用（`blr x30`），说明徽位对象
   有多态：泛音徽位与按音徽位返回不同的值（泛音走 2.1 的表，按音走另一
   套——这就是经验拟合失败的根因：我无法从静态数据区分二者）。
3. 最后加 `Nab` 的全局转调（下标 7），把"绝对音名"对齐到当前 `1=?`。

### 弦号表的两套等价表达

`STRING_FIFTH=[-5,-3,0,2,4,7,9]`（相对 F）和 `STRING_OFFSET=[0,2,5,7,9,12,14]`
（相对 C）是**同一组定弦的两种零点**：

```
弦:        1    2    3    4    5    6    7
绝对音名:  C    D    F    G    A    C    D    (正调)
相对C:     0    2    5    7    9   12   14   <- STRING_OFFSET
相对F:    -5   -3    0    2    4    7    9    <- STRING_FIFTH
```

第 6、7 弦在"相对 C"里是 12、14（高八度），在"相对 F"里折回成 7、9
（同音级），这正是路径 B 用 FIFTH 表、路径 A 用 MAJ 表时八度归属不同的
体现。

## 4. 不匹配检测与"建议替换减字"（★★）

### 检测器位置
`UIk` 库 `IZa` 类的一组闭包，紧挨着错误字符串（`pp+0x135f0` 起）：

```
0x135f0 "泛音徽位不正确 "
0x135f8 "泛音徽位不正确，当前音位是按音"
0x13600 "按音徽位不正确 "
0x13608 "按音徽位不正确，当前徽位是泛音"
0x136b8 "检测错误"
```

闭包签名（来自 `asm/uik.dart`）：

| 地址 | 返回类型 | 作用 |
|---|---|---|
| `0x63640c` | `bool` | 徽位合法性校验（泛音/按音错配） |
| `0x6362ec` | `qZa` | 同上，返回诊断对象 |
| `0x634f88` | `kab?` | **返回建议替换的减字**（`kab?` = 可空音符对象） |
| `0x636e50` | `kab?` | 同上，另一分支 |

`0x634f88` 返回 `kab?` 就是用户描述的"点一下就替换成正确减字"的那个候选
生成器。它的逻辑是：拿路径 A 算出的目标音高，**枚举**所有 (弦,徽) 组合，
找出能产生同一音高的合法减字作为候选。

### 枚举器（`0x63dc00`，KZa 类内）

```
0x63dc80  ldr 13徽表
0x63dc90  cmp i,#0xd            ; i < 13
0x63dc98  ldr HUI_TAB[i]
0x63dcc0  bl 0x63df2c           ; 用 (弦, HUI_TAB[i]) 试算
0x63dd64  b   0x63dc7c          ; 循环 13 个徽
```

这就是"给定一个音高，遍历 13 个徽位、7 根弦，列出所有等音减字"的反查。
结合路径 A 的目标音高，就能给出替换候选列表。

### 键盘事件类型校验（`0x67d7bc`，`SIk_FZa::_Tjh`）
```
0x29a58 "错误：选中类型和键盘事件类型不匹配"
```
用户在简谱位输入减字、或在减字位输入简谱数字时触发——属于输入法层面的
类型校验，不涉及音高计算。

## 7. 待办 / 进一步验证

要把"徽位贡献"那一项（路径 B 里的 `blr` 虚调用）彻底钉死，需要：

1. **动态 hook**：用 `frida_decode_score_jians.py` 已有的 Gadget 通道，在
   `0x68f230` 的 `onEnter` 抓 `(弦号, 八度, 徽位对象)`、`onLeave` 抓返回
   的绝对音高数，几张谱面跑一遍即可拟合出泛音/按音两套徽位函数的确切值。
2. **单步仿真**：用 unicorn 加载 `libapp.so` 的 `.text+.rodata`，把虚表
   解开，对 `0x68f230` 做符号执行，直接拿到徽位虚函数的返回表达式。

以上两项任选其一，即可把本报告里 ★ 的部分补成 ★★★。当前报告的算法
**骨架（四张表 + 路径 A/B 公式 + 不匹配检测位置）已由反汇编直接确认**，
不依赖经验拟合。
