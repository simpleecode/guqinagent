一句话总结：用 GEPA、ReAct 证明系统竞争力，用 SFT 和架构消融验证方法贡献，用古琴专家评估和现代曲测试验证实际价值与泛化能力。

## 一、最终实验方案

我建议整理成下面这张表：

| 实验方法              | 模型       | 架构  | Warning | 实验目的                 |
| ----------------- | -------- | --- | ------- | -------------------- |
| Vanilla ReAct     | 闭源 API   | 单阶段 | ✅       | 通用 Agent Baseline    |
| GEPA              | 同一闭源 API | 单阶段 | ✅       | 强 Prompt 优化 Baseline |
| Artifact-only SFT | 本地 9B    | 单阶段 | ✅       | 验证轨迹训练的价值            |
| Trajectory SFT    | 本地 9B    | 单阶段 | ✅       | 验证两阶段架构的价值           |
| No Warning        | 本地 9B    | 双阶段 | ❌       | 验证 Warning 的价值       |
| GuqinAgent (Ours) | 本地 9B    | 双阶段 | ✅       | 完整方法                 |

这里有三个重要说明。

1\. Artifact-only SFT：你的设计可以。

单阶段，使用 `get_pitch_candidates` 和 `edit_plan`，配合固定推理步骤。

但训练监督只来自专家最终减字谱，不包含 Teacher 的工具交互轨迹。固定推理步骤应属于推理时 Prompt，而非从参考答案构造的训练推理链。

此外，评估轨迹训练的价值时，应该比较：

Artifact-only SFT vs Single-stage Trajectory SFT。

这样才能尽量排除两阶段结构造成的差异。

2\. Warning：建议做两个消融版本。

都采用双阶段架构：

- Inference-only No Warning：使用同一个训练好的 GuqinAgent，只在推理时关闭 Warning。
- Full No Warning：Teacher 构造训练轨迹时无 Warning，Student 推理时也无 Warning。

第一个直接验证推理反馈的作用；第二个验证从训练数据构造到推理都移除 Warning 的整体影响。

注意：Full No Warning 可能同时改变训练轨迹的质量和分布，不能把结果全部归因于推理反馈。如果资源允许，可以再做训练与推理两个因素的完整 2×2 实验。

3\. ReAct 和 GEPA：同一个闭源 API 模型。

两者使用相同工具、Warning、基础领域手册及推理预算，GEPA 只额外进行 Prompt 优化。

GEPA 官方实现支持利用执行轨迹与文本反馈优化 Prompt，很适合这种工具 Agent。

但闭源 API 与本地 9B 模型的能力有差异，因此它们属于系统级竞争基线。要证明你自己方法的组件贡献，主要还是依靠本地模型的受控消融。

## 二、古琴专家应该评估哪些方法？

我建议专家评估以下 5 组最终输出：

| 方法                          | 为什么需要专家评估      |
| --------------------------- | -------------- |
| GuqinAgent (Ours)           | 检验最终演奏质量       |
| GEPA                        | 与强 Baseline 比较 |
| Vanilla ReAct               | 与通用 Agent 比较   |
| Artifact-only SFT           | 检验轨迹训练的音乐价值    |
| Single-stage Trajectory SFT | 检验两阶段带来的音乐价值   |

不必让专家评估全部消融变体，Warning 的作用主要由自动指标和针对性错误分析验证即可。

### 专家具体评估什么？

我建议采用 1–5 分量表：

| 评估维度     | 主要内容             |
| -------- | ---------------- |
| 音高与旋律准确性 | 是否忠实于原始简谱        |
| 指法合理性    | 弦、徽位、左右手操作是否合理   |
| 技法合理性    | 绰、注、吟、猱等使用是否恰当   |
| 演奏连贯性    | 换弦、手位移动、余音处理是否自然 |
| 整体演奏质量   | 专家是否认为结果适合实际演奏   |

另外增加一个特别有说服力的问题：

“如果需要实际演奏，你更愿意直接使用哪份减字谱？”

让至少两位专家在不知道模型来源的情况下独立评分，同时记录评分一致性。

如果专家评估工作量太大，可以在所有方法共享的一组乐段上开展盲评，而不是给不同模型选择不同测试片段。

## 三、10 首现代曲怎么评估？

这个设计我很支持。

因为古谱测试和现代曲测试回答的是不同的问题：

| 数据集     | 主要验证什么           |
| ------- | ---------------- |
| 古谱测试集   | 对传统古琴记谱任务的性能     |
| 10 首现代曲 | 对新旋律和不同音乐风格的适应能力 |

现代曲建议：

- 在实验前固定 10 首曲目，不根据结果筛选。
- 确保没有进入 SFT 数据或 GEPA 的优化数据。
- 尽量覆盖不同速度、音域、旋律复杂度。
- 统一改编约束，避免不可演奏的音域或复调要求影响比较。
- 所有方法使用同一输入。

自动评估仍然可以计算 Pitch Success、Coverage、Rule Violations 等指标，因为目标音高来自输入简谱，不一定需要专家参考减字谱。

专家评估重点比较五种方法的最终减字谱。

如果每首现代曲均评估五种方法，就是 50 份结果。由两位专家评分，总计 100 份评分任务，工作量需要提前确认。

另外，我建议现代曲的结果单独成表，称为 Modern-melody Generalization，不要直接并入古谱主测试集。
