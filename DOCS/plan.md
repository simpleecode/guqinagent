# GuqinAgent 论文实验与修改计划

> **核心思路：** 通过 ReAct 与 GEPA 评估系统竞争力，通过轨迹监督、两阶段架构和 Warning 消融验证方法贡献，并结合古谱测试、现代曲测试及古琴专家盲评检验实际效果与泛化能力。

## 一、核心研究问题

论文的 Method 和 Experiments 围绕以下三个研究问题展开：

| 研究问题 | 核心假设 | 关键对照 |
| --- | --- | --- |
| **RQ1：轨迹监督** | 从专家减字谱逆向构造的工具交互轨迹，是否优于直接学习最终减字谱？ | Artifact-only SFT vs. Single-stage Trajectory SFT |
| **RQ2：两阶段架构** | 将基础指法生成与技法优化分离，是否优于单阶段生成？ | Single-stage Trajectory SFT vs. GuqinAgent |
| **RQ3：Warning 反馈** | Warning 是否能够有效指导错误修复并改善最终结果？ | GuqinAgent vs. No-Warning 消融 |

研究目标不是预设所有设计均有效，而是通过受控实验量化各模块的收益、代价与适用边界。

## 二、主实验与 Baseline

| 方法 | 基础模型 | 推理架构 | 推理时 Warning | 主要用途 |
| --- | --- | --- | --- | --- |
| **Vanilla ReAct** | 闭源 API 模型 | 单阶段 | 开启 | 通用工具 Agent 基线 |
| **GEPA** | 与 ReAct 相同的闭源 API 模型 | 单阶段 | 开启 | Prompt 优化强基线 |
| **Artifact-only SFT** | 本地 9B | 单阶段 | 开启 | 检验直接学习最终减字谱的效果 |
| **Single-stage Trajectory SFT** | 本地 9B | 单阶段 | 开启 | 作为轨迹监督与两阶段架构的共同对照 |
| **GuqinAgent (Ours)** | 本地 9B | 双阶段 | 开启 | 完整方法 |
| **No-Warning Ablations** | 本地 9B | 双阶段 | 关闭 | 检验 Warning 的影响 |

### 2.1 Artifact-only SFT

- 采用**单阶段**推理，保留 `get_pitch_candidates` 和 `edit_plan` 工具。
- 使用固定、通用的推理步骤（Prompt），不将参考答案或 Teacher 的隐藏信息嵌入推理过程。
- 训练监督仅来自专家最终减字谱，不使用 Teacher 构造的工具调用、工具反馈或编辑轨迹。
- **核心比较：** Artifact-only SFT vs. Single-stage Trajectory SFT。尽量对齐基础模型、训练曲目、工具环境和推理预算，以隔离轨迹监督的影响。

### 2.2 Warning 消融

两种消融均沿用**双阶段架构**：

1. **Inference-only No Warning：** 使用完整 GuqinAgent 的训练权重，仅在推理阶段关闭 Warning，测量推理时反馈的直接作用。
2. **Full No Warning：** Teacher 构造训练轨迹时不接收 Warning，Student 推理时也不接收 Warning；使用对应轨迹重新训练，测量完整反馈机制的整体作用。

需区分两种结论：前者主要反映**推理时 Warning 的贡献**；后者同时改变训练监督和推理反馈，不能将差异全部归因于推理阶段。若资源允许，可补充训练阶段 × 推理阶段的 2×2 因子消融。

### 2.3 ReAct 与 GEPA 的公平比较

- 两者采用**相同的闭源 API 基础模型**，并共享工具、领域规则、Warning 和运行环境。
- 保持可比较的推理调用或 token 预算；单独记录 GEPA 的离线 Prompt 搜索成本。
- GEPA 只优化预先规定的 Prompt，不修改测试集、Runtime 或领域规则。
- 闭源 API 与本地 9B 存在基础能力差异，因此 ReAct/GEPA 主要用于**系统级比较**；关于训练和架构贡献的因果判断，以本地 9B 的受控实验为主。

## 三、测试数据与评测协议

| 测试集合 | 目的 | 评测重点 |
| --- | --- | --- |
| **古谱测试集** | 测量传统古琴记谱任务上的表现 | 音高正确性、覆盖率、规则符合性、参考一致性 |
| **10 首现代曲** | 考察面对新旋律和不同音乐风格时的适应能力 | 音高正确性、规则符合性、实际可演奏性与音乐表现 |

正式测试前应固定测试曲目、划分、预处理流程、Runtime 版本、评测指标和预算，避免根据测试结果反复调整模型或 Prompt。

### 3.1 自动评测

以**最终输出的完整减字谱**为主要评价对象，统一报告：

- **Pitch Success：** 在预先定义的有效目标音高事件中，最终输出音高正确的比例。
- **Pitch Coverage / Pitch Accuracy：** 分别报告可解析覆盖率和条件音高准确率，避免仅比较可解析事件导致偏差。
- **Rule Violation Rate：** 最终输出中的演奏与记谱约束违反情况。
- **Technique / Ornament 指标：** 与专家参考的技法一致性；将其解释为参考一致性，而非唯一的演奏正确性。
- **推理成本：** token、工具调用次数和运行时间等。

现代曲即使没有对应的专家减字谱，也可以依据输入简谱计算音高相关指标；缺乏可靠参考标注的指标应标记为不适用，不应强行计算。

### 3.2 现代曲测试原则

- 预先确定 10 首曲目，避免根据实验结果挑选。
- 确保曲目未用于 SFT、GEPA 优化或其他模型选择环节，并检查可能的旋律重叠。
- 尽量覆盖不同速度、音域和旋律复杂度，明确统一的改编限制。
- 所有模型使用相同输入，结果与古谱主测试集**分开报告**，设置独立的 *Modern-melody Generalization* 小节。

## 四、古琴专家盲评

### 4.1 参与比较的方法

建议评估以下 **5 组方法的最终减字谱**：

1. GuqinAgent (Ours)
2. GEPA
3. Vanilla ReAct
4. Artifact-only SFT
5. Single-stage Trajectory SFT

不必对全部 Warning 消融方法开展完整专家盲评；Warning 的作用主要通过自动指标和有针对性的错误案例进行分析。

### 4.2 专家评分维度

建议采用 **1–5 分量表**：

| 维度 | 评价要点 |
| --- | --- |
| **音高与旋律准确性** | 是否忠实表达输入简谱的旋律与音高 |
| **指法合理性** | 弦位、徽位及左右手安排是否合理 |
| **技法合理性** | 绰、注、吟、猱等技法的使用是否恰当 |
| **演奏连贯性** | 换弦、手位移动、余音衔接等是否自然 |
| **整体演奏质量** | 最终减字谱的可演奏性和音乐表达是否令人满意 |

可增加一道整体偏好题：**“如果需要实际演奏，您更愿意采用哪份减字谱？”**

至少邀请两位专家独立、盲法评分，并统计评审一致性。专家只看到统一格式的输入与最终结果，不显示模型名称或中间推理过程。

若在全部 10 首现代曲上评估上述 5 种方法，将产生 **50 份最终结果**；由 2 位专家分别评分，共 **100 次结果评审**。如工作量较大，可预先选择各方法共享的代表性乐段进行评价，不能为不同方法选择不同片段。

## 五、论文结构与实验对应关系

| 论文部分 | 主要内容 |
| --- | --- |
| **Introduction** | 明确任务挑战、研究动机及 RQ1–RQ3 |
| **Related Work** | 补充 ReAct、GEPA、从最终成果构造过程监督等相关研究，明确创新边界 |
| **Method** | 介绍专家成果引导的轨迹构造、两阶段生成及 Warning 反馈机制 |

| **Ablation Studies** | 围绕 RQ1–RQ3 报告轨迹监督、两阶段架构及 Warning 消融 |
| **Generalization & Human Evaluation** | 10 首现代曲测试、专家盲评与典型错误分析 |
| **Discussion** | 解释方法收益、额外开销、失败模式和适用边界 |

## 六、实施顺序

1. **冻结评测协议。** 固定古谱测试集、10 首现代曲、评测指标、Runtime 与实验预算。
2. **完成核心 Baseline。** 实现 Vanilla ReAct、GEPA 和 Artifact-only SFT，并验证运行条件一致性。
3. **完成主要消融。** 运行 Single-stage Trajectory SFT、两阶段比较及两种 No-Warning 设置。
4. **运行正式测试。** 使用最终选定的模型与 Prompt，在古谱和现代曲测试集上统一生成结果。
5. **开展专家评估与统计分析。** 完成盲评、错误类型分析、置信区间及成本比较。
6. **根据证据完善论文。** 更新实验表格、结果分析及贡献表述，使结论与实验证据相匹配。

> **写作原则：** 当前即可完善 Method、评测协议与实验设计；Introduction 中的最终贡献表述，以及 Abstract 和 Conclusion 的结论性表述，应在主要实验完成后定稿。

**最终目标：** 每个核心设计对应明确的研究假设、可复现的对照实验和基于实际结果的结论，形成一条可审查的科研证据链。
