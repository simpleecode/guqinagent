# 单阶段训练与 warning 推理消融

## 单阶段数据质量修复

- 正式集：`ABC_J/agent_training/single_stage_audited`，3976 phrase / 3976 单阶段轨迹。
- `.quality_rebuild` 维护唯一当前选集、运行时快照、重造产物及报告。
- 新规则重审沿用教师生成时实际使用的参考历史，不用模型生成历史替代该条件。
- 初筛：1074 phrase / 2155 warning；完整 Qwen3.5 AutoProcessor 模板下56条超过8192 token；交集30，合并1100 phrase。
- 只重造1100条，GLM-5.3、7 worker、间隔0.5秒、24工具轮、最多3次尝试；不截断、不删轮次来压短。
- 生成使用独立固定快照，与推理消融代码隔离。保留原始证据，验收前不覆盖正式集。
- 完成后核验ID、真实工具调用、accepted plan；按同参考历史重审，报告残留和新告警。
- 模型脱敏后按sample_id精确替换单阶段回合，工具调用及回执不变；不能直接套用写死7952条/两阶段pair的合并器。
- 再导出3976条单阶段SFT并校验、统计长度、泄漏检查；新旧正式版可恢复替换。仍超长如实报告，不承诺重造一定变短。
- 数据验收后才提交训练：Qwen3.5-9B、相同LoRA/学习率/epoch/cutoff8192设置，有效batch12；单阶段数据规模较两阶段少一半，不强行增加epoch补齐步数，报告训练token及步数。

## 同权重推理端消融（用户已确认）

- 主对比使用同一两阶段学生权重，不重造无warning教师，不另训模型。
- 固定公开输入、权重指纹、运行时、工具、种子、采样 .6/.3/0、最大轮数及截断处理。
- ON：公开warning/hint、音高警告后续编辑提醒、warning-stop提醒、warning触发Guqinizer追加pass。
- OFF：`--warning-feedback off` 隐藏上述warning/hint及提示表中的告警，关闭由告警触发的修复提醒和追加pass。
- 两组都保留必要的协议/格式/完整性校验和音高候选工具；结构错误和截断仍可重试。OFF不是跳过最终评估。
- hint也属于建议反馈，随warning一起关闭；该消融估计完整诊断反馈机制的作用，不能声称仅单一warning规则的净效应。
- 所有最终方案都用同一完整运行时离线评分；统计PitchAcc、指法/音色/装饰F1、warning、协议失败、截断、工具轮数和生成token。失败不能剔除。
- 先排33段固定试点（沿用sampling pilot公开输入：4首），两组各33段，不用不同参数的旧结果当ON对照。
- 试点通过实际请求/工具回执无泄漏和停止策略核验后，再安排原始47首979段的同条件全量双臂；不混入新幽兰或黑名单谱。
- 独立目录：`train/eval_outputs/warning_ablation/pilot/{on,off}`；远端使用`.warning_ablation_runtime`隔离环境，不覆盖主评估/Mark1。
- 单seed小样本只作实现与方向检查；正式论文结果需说明种子、成本和重复试验安排。
- 实现回归：新增反馈开关及停止策略7项测试通过；较宽的235项测试有5项既存失败，在消融改动前的生成快照上同样失败（旧提示词断言、旧走手阈值及休止继承断言等），不得报告全套全绿。
